Grid forming

  1. A continuation of P2, the ESP32 Ultrasonic Radar. I treated the finished radar as a device under test and characterized it across six tests, with limits set before measuring and before/after data for every fix.

    Stack
    AD3 · WaveForms · Python (dwfpy, pyserial, matplotlib)
    Tests
    Signal level, distance accuracy, echo timing, loop timing, servo PWM, rail droop
    Found
    5 V on a 3.3 V pin, 1% speed-of-sound error, pulseIn stall
    Result
    RMS error 0.92 → 0.63 cm, loop 106 → 86 ms, ECHO 5.05 → 3.41 V
    Hard part
    Stale serial buffers and auto-reset on port open

    Engineer's notes

    • Measured the HC-SR04 ECHO at 5.05 V going into a 3.3 V GPIO; added a resistor divider and re-measured at 3.41 V.
    • Distance error grew with range; traced it to a speed-of-sound constant about 1% low. Fix moved the fit slope from 0.961 to 0.990.
    • With nothing in range, pulseIn waited out a 48 ms echo every ping. A 30 ms timeout cut the loop from 106 to 86 ms.
    • Readings that seemed stuck turned out to be stale serial data. Proved the sensor was fine with a three-probe logic capture and minimal sketches, then fixed the test script.
    • Found readings jumping by exactly one 40 kHz wavelength (0.43 cm): the sensor detecting a weak echo a cycle late.

  2. An HC-SR04 sweeps from 15° to 165° on an SG90 servo while C++ firmware draws range rings, a live sweep line and persistent detections on a 128×64 SSD1306 OLED. No PC in the loop.

    Stack
    ESP32 · C++ · I²C · PWM
    Sensing
    Ultrasonic time-of-flight, 40 cm window
    Display
    SSD1306 over I²C on GPIO 32 / 33
    Debug tools
    Multimeter · serial logging
    Hard part
    Timer conflict, strapping pins, I²C remap

    Engineer's notes

    • Servo and display worked alone but failed together. Isolated each in a minimal sketch, then reintroduced them one at a time, which surfaced three separate faults.
    • Moved every signal off the ESP32 strapping pins after finding they were changing the boot mode.
    • Fixed a silent display by remapping I²C explicitly with Wire.begin(32, 33).
    • Next: move to a timer-driven, non-blocking loop.
    • Characterized and fixed in P1: Radar Test & Characterization.

  3. Taken from gear geometry to dimensioned drawings to printed, tested parts on a Raspberry Pi 4 controlled Q-arm.

    Stack
    Autodesk Inventor · 3D printing · Python
    Team
    McMaster 1P13 design project
    Owned
    Gear CAD, drawings, sign_up(), pack_products()

    Engineer's notes

    • A week before the deadline, testing showed the arms were too wide and knocked neighbouring items. We narrowed them and lengthened the tips over several reprints.
    • Iterated through printed prototypes to validate grip on the physical arm.
    • Cut manual handling effort by roughly 95% in the project scenario.

  4. A Parallax PING sensor watching for a car, a servo doing the work, and a stepped sweep with threshold logic to avoid false triggers.

    Stack
    Arduino · C++ · ultrasonic sensing
    Trigger
    Object within 5 cm
    Motion
    Servo steps 2° every 15 ms
    Note
    First thing I built that ran unattended

    Engineer's notes

    • Threshold logic mattered more than the sensor: most of the tuning went into ignoring things that weren't cars.
    • A hard servo.write(90) snapped the gate open, so I replaced it with a stepped loop for smooth motion.

  5. Aluminum foil contact bumpers, continuous rotation servos, and a state machine that reroutes on contact.

    Stack
    Arduino · C++ · contact sensing
    Inputs
    Two foil bumpers on pins 8 and 9
    Drive
    Two continuous-rotation servos
    Note
    State machines, before a course taught them

    Engineer's notes

    • Crude sensing, honest logic. Taught me to design the states before writing the code.
    • Tuned the reverse (500 ms) and turn (800 ms) over repeated runs: shorter re-hit the wall, longer overshot.
